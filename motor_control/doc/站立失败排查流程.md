# 站立失败排查流程（站不起来 / 中途突然掉落）

> 建立于 2026-07-05，针对当日现象：站立过程中机器人突然掉落、无法完成站立。
> 配套文档：[站立起不来原因分析.md](站立起不来原因分析.md)（各原因机理详解，本文引用为「原因分析 §N」）、
> [站立真机调试方案.md](站立真机调试方案.md)（Stage 0~4 分级测试法）。
> 工具：`robot_web.py` 网页（角度跟踪图 / 扭矩监控图 / 日志）+ `motor_ctrl read`。

---

## 本机当前已知风险点（排查前必读）

按 2026-07-05 当天状态，以下是**本机特有**、优先级高于通用原因的嫌疑：

| # | 风险点 | 与"突然掉落"的关系 |
|---|--------|--------------------|
| 1 | **FR 大腿摇臂错位史**：当日发现 fr_thigh/fr_shank 相对标定偏了 +18.5°（≈360°/20，疑摇臂错装/滑动一齿），已用重锚修复，但**机械根因未确认** | 若摇臂夹紧不牢，站立负载（远大于趴姿）下**会再次滑齿**——滑齿瞬间该腿突然折塌，正是"突然掉下去"的形态。**头号嫌疑** |
| 2 | **重锚的前提未验证**：重锚假设"趴→站行程（delta）没变"。若 FR 腿当初不是纯零点平移而是连杆几何变了，FR 的站姿目标就是错的 | FR 腿到位姿态不对称 → 重心偏 → 侧翻/塌落 |
| 3 | **小腿可被重力反驱**：当日实测小腿断电/零增益下以几°/分钟下滑，静摩擦挡不住自重 | 说明小腿全靠电机出力撑着；电机一旦失力（保护/断令）腿立即塌 |
| 4 | **当日曾出现 12 电机集体无响应**（疑似电机电源被关/掉电） | 若供电环节不可靠（接头松、电源保护），站立大电流时掉电 → 整机同时瘫软 |
| 5 | `execute.k_p=25`（转子侧）已贴协议上限 25.599 | 刚度大 → 电流峰值大 → 更容易触发电源/过流环节的问题 |

---

## 第 0 步：安全准备

- 机器人**吊空或架空**（腿够不到地/障碍），排查阶段一律不落地。
- 网页开着，**空格键=急停**随时可按。
- **趴姿上电**（离趴姿 < 半转子圈 ≈28° 关节，让整圈归一对到正确的圈，原因分析 §8）。
- 起一次记录：拍视频（掉落瞬间形态是最重要的证据）、日志别清。

---

## 第 1 步：受控复现一次，按「掉落形态」分类

用慢参数（速度 0.05、最小时长 5s、分段抬升开）复现一次，盯着看**怎么掉的**：

| 掉落形态 | 指向 | 跳到 |
|----------|------|------|
| **12 个关节同时瘫软**，像断电一样 | 电源 brownout / 供电掉电 | 分支 B |
| **一条腿的 3 个关节**同时瘫，其他腿还撑着 | 该腿总线/servo 进程断（一腿=一路 ttyUSB） | 分支 E |
| **单个关节突然折**，其他关节还在出力 | 该电机保护(merr) 或 机械滑齿 | 分支 A / C |
| **缓慢下沉**，不是突然掉 | 扭矩不足/刚度不足（"误差小却下沉"） | 分支 D |
| 站到某一段（shank/thigh/hip）必掉 | 该段峰值力矩/电流问题 | 分支 B / D |
| 点站立**根本不动、被拒绝** | 安全校验/配置/无响应（原因分析 §6） | 先解决拒绝原因 |
| FR 腿到位姿态和其他腿**明显不对称** | 重锚 delta 失效 | 分支 F |

记录：掉在哪一段、哪条腿先掉、当时扭矩图各柱高度、温度列数值。

---

## 第 2 步：掉落后立即取证（先别挪机器人）

掉落后机器人保持原地，按顺序取证：

1. **读角度**：点「📐 读取当前 12 关节角」，对照物理姿势判断：
   - 某关节**读数和肉眼位置对不上**、且差值稳定（如 ~18°、~56.9° 整圈之外的固定角）→ **机械滑齿签名** → 分支 C。
     判别方法：把该腿手动摆回趴姿再读，看偏差是否还是那个固定值。
   - 读数与物理位置一致 → 不是滑齿，继续。
2. **看温度/错误**：关节表 `temp` 列 ≥85℃ 或 `merr`≠0（1=过热 2=过流）→ 分支 A。
3. **翻日志**（从掉落时刻往前找）：
   - `[警告] servo /dev/ttyUSBx 管道已断开` → 分支 E；
   - `[未到位] … 力矩/电流不足` → 分支 D；
   - 什么警告都没有、FB 突然全停 → 分支 B（掉电时来不及留日志）。
4. **看扭矩峰值**：扭矩监控图柱顶横杠（tau_peak）——掉落前是否顶到上限参考线。

## 第 3 步：分支排查

### 分支 A：电机保护（过热/过流）

- 签名：单电机突然失力；`temp` 接近 90℃ 或 `merr`≠0；**保护后需重新上电**才恢复。
- 处置：等冷却 → 重新上电 → 用更低的动态负载再试（调慢 + 分段 + 前馈，原因分析 §2/§3/§4）。
- 若总是同一个电机过热：查该关节是否长期出大力（对照 tau_peak），考虑前馈 t_ff 分担或机械配重。

### 分支 B：电源 brownout / 供电不可靠 ⚠ 当日有前科

- 签名：**多电机/整机同时瘫软**，日志无警告，FB 全停；恢复供电后电机又能读。
- 排查：
  1. 先复查**当日"12 电机集体无响应"** 的原因——电源开关？接头？电源保护自锁？这个没弄清之前，一切站立测试的掉落都可能是它。
  2. 万用表/示波器量**站立中段**母线电压（从趴到站中段腿最伸展、电流峰值最大，原因分析 §2）：电压塌 → 电源功率/电池不够或线阻太大。
  3. 粗算功率预算：12 × 单电机峰值电流 × 母线电压，对照电源额定；分段抬升（每段只 4 电机）就是为压这个峰值。
- 处置：换大电源/满电电池、加粗供电线、紧固接头；保持分段抬升开。

### 分支 C：机械滑齿（摇臂/连杆错位）⚠ 本机头号嫌疑

- 签名：掉落后某关节出现**新的固定角度偏差**（第 2 步取证 1）；滑齿瞬间常有"咔"声；重点怀疑 **FR 大腿**（有 18.5° 错位前科）。
- 排查（**画线法**）：
  1. 趴姿下，用记号笔在**电机输出法兰—摇臂—连杆**上跨零件画一条直线（12 个关节都画，重点 FR）；
  2. 做一次站立（吊空）→ 回趴 → 逐关节检查记号线是否错开；
  3. 错开的关节 = 滑齿点，检查其夹紧螺丝/键/齿面。
- 处置（完整修复流程）：
  1. **定位滑动面**：画线法确定错开发生在哪个界面——摩擦夹紧面（轴—摇臂）/ 花键齿形安装面
     （错位量=齿距整数倍，本机 18.5°≈360/20 指向 20 齿安装面错一齿）/ 齿轮啮合副跳齿；
  2. **拆开评估损伤**：齿面/键完好只是错位 → 可复位重装；齿剪断/磨圆/塑性变形（打印件常见）
     → 复位必再滑，必须换件；
  3. **按类型修**：摩擦夹紧 → 接触面除油+按扭矩上紧+螺纹胶，反复滑则改形锁（定位销/D 面/滚花）；
     花键错齿 → 对准原齿位重装，检查齿形；齿轮跳齿 → 查中心距被撑大/轴承座变形，
     加大齿宽/模数或换材料；
  4. **静态扭矩验证**：吊空「只测这条腿」锁位保持，手掰关节加力到 `实测 tau_peak×6.33×1.5~2`
     （参考上限：GO-M8010-6 输出侧峰值 ≈23.7 N·m ≈ 0.3 m 力臂上 8 kg 力），记号线不错开才算修好；
  5. **重新标定**（滑齿后原标定作废）：对准原齿位复位的用「🔁 重锚趴姿（保持Δ）」；
     动过连杆几何的走 ①②③ 完整标定；同步 `deploy/real/config/mos2026_2.yaml` 的 `stand_rotor`；
  6. **推广检查其余 11 关节**：同款设计一处滑处处可能滑，至少全部紧固+画线留监控，
     承重关节（thigh/shank）做静态扭矩测试。
- 滑齿修复前**不要落地测试**——负载越大滑得越狠。

### 分支 D：扭矩/刚度不足（缓慢下沉型）

- 签名：不是突然掉，是撑不住往下出溜；`[未到位]` 日志；扭矩柱顶上限 + 跟踪误差大。
- 按原因分析 §1~§4 的顺序调：调慢（速度 0.05 / 时长 5s）→ 前馈 t_ff（小步试，符号对准）→ K_P/K_W 微调。
- 注意本机小腿反驱特性（风险点 3）：小腿 t_ff 前馈是合理的长期方案。

### 分支 E：总线 / servo 进程断

- 签名：一条腿 3 关节同瘫；日志有 `管道已断开`；或该腿 FB 列全空。
- 排查：USB 线/hub 供电、`ls /dev/ttyUSB*` 是否掉号重排（udev 固定别名可避免）、`motor_ctrl read` 单读该腿。
- 另注意：**motor_ctrl 曾因仓库改名 rpath 失效**（2026-07-05 修过）——二进制无法启动时表现也是"无响应"，手跑 `motor_ctrl` 看是否报 `.so` 加载错误。

### 分支 F：重锚 delta 失效（FR 站姿目标错）

- 签名：站立能完成但 FR 腿到位姿态与其他三腿不对称；或 FR 在站立末段把整机顶翻。
- 验证：吊空用「只测这条腿」单独站 FR，对比 FL 的到位姿态（左右镜像应对称）。
- 处置：不对称 → delta 作废，走 ①记录趴姿 → ②手扶站姿 → ③保存 的完整标定；同步更新
  `deploy/real/config/mos2026_2.yaml` 的 `hardware.stand_rotor`。

---

## 第 4 步：修复后按 Stage 递进回归（单变量原则）

每次只改一个变量，按以下顺序回归，任一步不过就回第 3 步对应分支：

1. **吊空单腿**（「只测这条腿」，FR 优先）：到位、对称、跟踪误差 <3°、扭矩不顶上限、温度平稳；
2. **吊空整机分段站立**：三段全过、`[完成] 到位并保持`、保持 2 分钟不下沉不掉；
3. **着地有人扶**：慢参数，随时准备托住；
4. **着地独立站立**：保持 5 分钟，期间记录 tau_peak 与温度趋势。

---

## 第 5 步：留档

每次排查结束，把「现象 → 取证结果 → 根因 → 处置」追加到 `doc/问题记录/`，
标定有改动的同时检查 `deploy/real/config/mos2026_2.yaml` 是否需要同步。

## 附：速查

```bash
# 单电机读角（滑齿取证）
motor_control/Linux/build/motor_ctrl /dev/ttyUSB0 1 read

# 兜底杀掉所有残留 servo 子进程（怀疑双重驱动时）
pkill -f "motor_ctrl .* servo"
```

- 界面所有「°」是**关节角**（已÷6.33）；FB 的 `tau` 是**转子侧** N·m，关节侧=×6.33。
- 1 转子整圈 = 56.9° 关节；掉电清圈只以 56.9° 整数倍出现且已自动归一（原因分析 §8）。
- K_P 协议上限 25.599（转子侧）；温度 ~90℃ 触发过热保护（merr=1），过流 merr=2，保护后需重新上电。
- 标定三件套：完整标定（①②③）/ 重锚趴姿（保持Δ，仅零点平移时可用）/ 备份在 `config/stand_config.bak.*.json`。
