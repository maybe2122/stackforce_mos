# 蹦跳步态问题诊断(pronking)

> 诊断对象:run `logs/rsl_rl/mos2026_2_closed_usd/2026-07-19_08-24-22`(PPO 基线,3000 iter,terrain curriculum)
> 评估方式:`scripts/rsl_rl/eval.py --terrain flat --num_envs 64`(完整报告见该 run 目录下 `eval/eval.md`)
> 日期:2026-07-19

## 一、现象

play 时机器人不是交替迈步行走,而是四条腿近似同步起落地"一蹦一蹦"前进(pronking/bounding)。

## 二、量化证据(eval 实测)

| 指标 | 实测值 | 正常参考 | 解读 |
|:---|:---:|:---:|:---|
| 对角同相位 | **1.00** | ≈1(trot 也是 1) | 对角腿同步 —— 单看正常 |
| 同端同相位 | **1.00** | **trot 应 ≈0** | 同侧前后腿也同步 → 四腿全同相 = pronk 实锤 |
| 平均占空比 | 0.00 | 0.5~0.65(走/小跑) | 脚几乎无稳定支撑相,全程弹跳 |
| 力矩近上限占比 | **65.9%**(fl_thigh 100% 饱和) | 应远低于 50% | 靠打满 16 N·m 硬弹,无力矩裕度 |
| 平均功率 / CoT | 1088 W / **11.15** | CoT 0.3~1.0 | 能耗超标一个量级 |
| vx 跟踪 | 指令 1.0 → 实际 0.85 | — | 跟踪平平,蹦跳本身低效 |
| 机身高度 / 倾斜 | 0.318(目标0.32)/ 0.05 | — | 姿态项正常,问题不在姿态 |

## 三、根因分析

### 1. 蹦跳是速度跟踪的"低成本局部最优"(主因)

四腿同步只需控制"一条虚拟腿",**不需要学腿间相位协调**,却同样能拿到速度跟踪奖励。
PPO 几乎必然先发现这个解;要把策略从这个局部最优推出去,约束项的梯度必须足够强。

### 2. 当前奖励权重压不住跟踪主项

当前配置(`reward_scales`):

```
track_lin_vel_xy:  6.0   ← 独大
anti_bound:       -0.5   ← 对症但太弱
feet_gait:         1.0
gait_symmetry:    -0.25
lin_vel_z:        -0.5
torque:           -0.0002 ← 幅值上几乎为零
joint_vel:        -0.0001
action_rate:      -0.005
```

力矩惩罚按实测值算:`0.0002 × Σ|τ|² ≈ 每步 0.06` 量级,对比跟踪奖励每步最高 6.0,
**策略打满力矩的代价可以忽略不计** → 直接导致 65.9% 的力矩饱和与暴力弹跳。

### 3. 次要/待排查因素

- **执行器增益**:落地回弹式的"被动蹦"通常是 Kp 偏高/阻尼偏低;本次相位证据指向主动 pronk,增益暂不列为主因,但调权重后若仍有落地弹跳需复查。
- **闭链被动关节储能**:Mos-One 闭链结构可能放大回弹,同上,先观察。
- **训练不充分**:收尾平均 episode 长度 471/1000,高难度地形还有约一半失败率;步态雕刻发生在训练中后期,当前确实还没收敛完。

## 四、建议的下一轮权重

| 项 | 现值 | 建议 | 目的 |
|:---|:---:|:---:|:---|
| `anti_bound` | -0.5 | **-2.0** | 直接打击同步蹦跳 |
| `feet_gait` | 1.0 | **2.0** | 强化目标步态相位 |
| `torque` | -0.0002 | **-0.001** | 逼出力矩裕度,治饱和 |
| `action_rate` | -0.005 | **-0.01** | 平滑动作 |
| `lin_vel_z` | -0.5 | **-1.0** | 再压垂直速度 |

其余不动;`track_lin_vel_xy` 保持 6.0(先加约束,不动主项,避免学不会走)。

## 五、验证方法

1. 训练中盯 SwanLab/TensorBoard:`anti_bound` 惩罚量应先增后收敛到近 0,`feet_gait` 应持续上升;
2. 训完跑 `eval.py`,验收标准:**同端同相位 < 0.3、占空比 > 0.45、力矩近上限占比 < 30%、CoT < 3**;
3. 与本次基线在 SwanLab 同项目下并排对比曲线。
