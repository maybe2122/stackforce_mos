# 真机部署 ① —— 角度映射标定 + 吊空验证（方案）

> 把 `传统步态/` 的 trot 步态往真机上搬的**第一步**：确立并验证「模型关节角 → 电机转子
> 指令」的映射，全程**机器人吊空、腿不承重**，只求「发下去的姿态/轨迹和模型一致、方向没
> 反、量级对」。**本阶段不下地、不追求走稳**——下地是后续里程碑。
>
> 前置结论见 [闭链运动学与MuJoCo行走.md](./闭链运动学与MuJoCo行走.md) §17。相关代码：
> `deploy/real/motor_bus.py`（**已有**的 rotor↔joint 映射）、
> `deploy/real/config/mos2026_2.yaml`（映射参数）、
> `motor_control/scripts/robot_web.py`（伺服流式底座）、
> `motor_control/config/stand_config.json`（原始电机标定）。

---

## 0. 关键前提：映射已经存在，本阶段是「验证复用」而非「从零标定」

调研后一个重要发现改变了整个方案：**rotor↔关节角的映射早就实现在
`deploy/real/motor_bus.py` 里**（为 RL 部署做的），每关节一条仿射：

```
rotor = stand_rotor + k·(q_sim − default)          k = gear·dir·sim_sign
q_sim = default + (rotor − stand_rotor)/k
```

参数在 `mos2026_2.yaml` 的 `hardware.joints`（`dir/sim_sign/stand_rotor`）+ 顶层
`default_dof_pos`。而且**传统步态的模型（`closed_chain_kin`，由 MJCF 来）与 Isaac 训练
环境（由 USD 来）是同一个资产**——MJCF 是 `usd_to_mjcf.py` 保轴转出来的，所以

> **θ_model（闭链模型关节角）== q_sim（Isaac/策略关节角）**（同零点、同符号、同关节）。

因此**传统步态的关节角可以直接喂进 `motor_bus.q_to_rotor()`**，不需要另起炉灶手工标定
偏置。本阶段的任务收敛为**三件验证**：

1. 证实 `θ_model == q_sim`（同 USD，桌面论证 + 一次数值抽检）；
2. 核实 YAML 里那套映射参数仍然对（尤其 `sim_sign` 标着「VERIFY on hardware」还没在真机
   上验过，全是 +1）；
3. **吊空**下先用 `SimMotorBus` 干跑、再上真机软增益慢放，确认姿态/轨迹/方向都对。

> 这比「拿铅垂线摆零位手标偏置」低风险得多，也复用了 RL 部署已经跑通的底座。

## 1. 范围（做什么 / 不做什么）

**做**：① 确认名称/机构对应；② 验证 `θ_model==q_sim` 与 YAML 映射（含 `sim_sign` 逐关节
方向核验）；③ 写吊空验证脚本（含 dry-run）；④ 给每步验收判据。

**不做**（后续里程碑）：下地承重、走稳、闭环平衡、增益调到走路值、连续行走。

## 2. 硬件接口速览（取自实际代码）

- **拓扑**：12 电机，每腿一路串口 3 个：`USB0`=FL(1,2,3)、`USB1`=FR(4,5,6)、
  `USB2`=RL(7,8,9)、`USB3`=RR(10,11,12)，顺序恒为 `hip,thigh,shank`。
- **减速比** `gear=6.33`；`data.Pos`=转子角，关节角=转子角/6.33。
- **读角**：`motor_ctrl <port> <id> read` → `ANGLE id=.. rotor=.. joint=.. deg=..`。
- **流式伺服**：`motor_ctrl <port> servo <kp> <kw>`（**转子侧**增益，上限 25.599）；
  stdin 逐行 `"<id> <pos_rotor> <tff> ..."`；`stop` 松力；FB 行
  `FB id=.. pos=.. vel=.. tau=.. temp=.. merr=.. ok=.. errd=..`；**一路串口一个进程**。
- **`motor_bus.py`** 已封装上面这套：`MotorBus`（真机）/ `SimMotorBus`（一阶跟随仿真，
  `make_bus(cfg, dry_run=True)`）、`JointMap.q_to_rotor/rotor_to_q`。

## 3. 名称与机构对应（易错，先钉死）

真机每腿 3 个电机命名 `hip/thigh/shank`，但**「shank 电机」驱动的是四连杆曲柄**（模型里
的 `*_shank_link`），真小腿 `*_shank` 是**被动**的。策略/YAML 的关节顺序（policy order）：

```
[fl_hip, fr_hip, rl_hip, rr_hip,  fl_thigh, fr_thigh, rl_thigh, rr_thigh,
 fl_shank, fr_shank, rl_shank, rr_shank]      # shank 槽位 = 模型 crank 通道
default_dof_pos = [0.15,0.15,-0.15,-0.15,  0,0,0,0,  0,0,0,0]
```

| 真机电机 | 模型受驱关节 | `closed_chain_kin` 输出 | 顺序槽位 |
|---|---|---|---|
| `*_hip` | `*_hip` | θ_hip | 0–3 |
| `*_thigh` | `*_thigh` | θ_thigh | 4–7 |
| **`*_shank`** | **`*_shank_link`（曲柄）** | **θ_crank** | 8–11 |

> `gait.py` 每腿输出 `(θ_hip,θ_thigh,θ_crank)`，装进 policy order 时 **crank 放 shank 槽**。

## 4. 映射与帧对齐

### 4.1 直接复用 motor_bus

对每个关节：`rotor = stand_rotor + gear·dir·sim_sign·(θ_model − default)`。
传统步态给 `θ_model`（policy order），逐关节调 `JointMap.q_to_rotor` 即得转子目标。反向
`rotor_to_q` 用于「读角→模型角→FK 自检」。

### 4.2 为什么 `θ_model == q_sim`（要点）

- MJCF 由 `tools/asset/usd_to_mjcf.py` 从 USD 转出，**关节轴 = `localRot1·unit_axis_USD`
  保轴**、零点一致；Isaac 直接读同一 USD。故两边 hip/thigh/shank_link 的关节角定义相同。
- `closed_chain_kin.leg_ik` 返回的 `θ_thigh/θ_crank` 就是 **MJCF qpos**（`solve_linkage`
  内部才用 `sgn_*` 转成平面角，输入/输出都是 MJCF 关节角），且 `--selftest` 已与 MuJoCo
  的 qpos 交叉验证到 1e-7。⇒ `θ_model` = MJCF qpos = USD 关节角 = `q_sim`。

### 4.3 桌面数值抽检（写进脚本 `check-frame`）

取几个模型姿态 θ_model，`q_to_rotor` 再 `rotor_to_q`，应完全复现（验正逆一致）；再把
`default_dof_pos` 当 θ_model 反算 rotor，应等于各关节 `stand_rotor`（映射锚点自洽）。

> ⚠️ 唯一可能不一致的是 **`sim_sign`**（USD/sim 轴符号残余修正，YAML 全 +1 但标注未在真机
> 验过）。§5.2 在真机上逐关节核。

## 5. 验证流程（吊空，逐步）

### 5.0 安全前置

1. 机器人**吊装/架空**，四腿悬空自由，脚下与行程内无人无物。
2. 急停可达（stdin `stop` / kill 脚本 / 断电）。
3. **软增益起步**：转子 `kp=2.0, kw=0.05`（≈关节侧 80/2，远低于走路的 12.5；方向弄反也
   不会爆冲）。
4. 先 `read` 12 电机：全 `ok=1`、温度正常、无 `err`。

### 5.1 确认对应（§3）

`read` 时手动扳一条腿的小腿，看哪个 id 的 rotor 在变，确认 `*_shank` 电机确随曲柄/小腿
联动；核对端口/ID 与 §3 表一致。

### 5.2 逐关节核验 `dir·sim_sign`（nudge-observe）

对每个关节，单独、缓慢：软增益锁当前位 → 目标 rotor **+0.05 rad**（极小）→ 看物理关节
朝哪转 → 对照 `θ_model` 增大该关节应朝哪转（hip 外摆＋、thigh 前摆＋、crank 见
`closed_chain_kin` 约定）。**同向 ⇒ 现有 `dir·sim_sign` 正确；反向 ⇒ 翻 `sim_sign`**
并记事。一次只动一个，动完回中。

> 这一步专治 memory 记过的「hip 轴前后镜像」「dir 装反」「FR 大腿错 18.5°」类事故。

### 5.3 静态站姿核对（对称性 + FK）

命令模型**静态站姿**（`gait` 冻结在站立相、`x_offset=-0.055`）经映射下发（软、限速），保持：

- **人眼**：四腿对称微撇、站高相当、无别劲/异响/过温；
- **数据**：`read` 12 电机 → `rotor_to_q` → 应复现模型左右对称（fl↔rr、fr↔rl 镜像，
  误差 < 5°）；过 `quad_fk` 四脚对称、站高误差 < 15 mm。

不对称/落点乱 ⇒ 某腿 `sim_sign` 或机构串了，回 §5.2 / §3。

### 5.4 锚点抽检（可选，增信）

对比 `θ_model==q_sim` 假设：把真机摆到「模型静态站姿」，读 rotor，与
`q_to_rotor(θ_stand)` 比，各关节差应 < ~0.1 rad 转子（含手工/机械误差）。差得大说明
`stand_rotor` 锚点漂了（真机被重定过零点）——重跑 `robot_web` 的站姿标定或 `_reanchor`。

## 6. 吊空验证脚本设计

`deploy/real/verify_gait_airborne.py`，**封装 `motor_bus.py`**（真机/`SimMotorBus`
二选一），轨迹来自 `传统步态/代码/gait.py`。

> **进度（2026-07-22）**：五个子命令全部搭好。
> - **无硬件、已自测通过**：`check-frame`（映射自洽+帧对齐）、`play-gait --dry-run`
>   （`SimMotorBus` 实时彩排，含整段预检+顺序双射+限速）。
> - **硬件三命令 `read` / `calib-dir` / `pose-stand`**：真机路径已搭好（软增益、限速、
>   在线预检、退出即松力），并用 `--dry-run` 在 `SimMotorBus` 上冒烟走通了控制流；
>   **但尚未在真实电机上跑过**——上真机前务必吊空、行程内无人无物。
>   - `calib-dir` 的操作面：每关节命令 `q_sim +nudge`，脚本先算并打印**该腿足端应朝哪
>     动多少 mm（FK 预测）**，操作者看真脚是否朝预测方向动来判 `sim_sign`；不一致则提示
>     翻转（**不自动改 YAML**，需人工确认后改）。
> ```bash
> python deploy/real/verify_gait_airborne.py check-frame
> python deploy/real/verify_gait_airborne.py play-gait --dry-run [--cycles N --period S --scale F]
> python deploy/real/verify_gait_airborne.py read|calib-dir|pose-stand [--dry-run] [--kp 2 --kw .05 --vmax 1]
> ```

### 6.1 子命令

| 命令 | 作用 | 安全 |
|---|---|---|
| `check-frame` | §4.3 正逆/锚点自洽（纯计算，`SimMotorBus`，**不碰硬件**） | 无硬件 |
| `read` | 读 12 电机 → `rotor_to_q` → `quad_fk` 打印四脚+站高 | 只读 |
| `calib-dir` | §5.2 逐关节 nudge，交互确认，回写 `sim_sign` | 微动 |
| `pose-stand` | §5.3 缓慢摆到模型静态站姿并保持，供核对 | 慢动 |
| `play-gait --air` | 空中慢放 **1** 个步态周期（`--cycles/--period` 放慢、`--scale` 缩幅），
  流式下发，逐帧记录「命令 vs 反馈」；结束松力 | 慢动 |
| `--dry-run` | 上述任何动作走 `SimMotorBus`，不连真电机，先验证管线 | 无硬件 |
| `stop` | 立即 `stop` 松力并退出 | 急停 |

### 6.2 数据流（play-gait）

```
gait.py → (θ_hip,θ_thigh,θ_crank)×4         （period 拉长到 2s、--scale 缩幅先小）
  → 装 policy order（crank→shank 槽）
  → JointMap.q_to_rotor 逐关节 → 12 个转子目标
  → 关节限速插值（默认 0.1 rad/s 关节侧）
  → 开跑前**整段预检**：越限位/跳变直接拒绝，不启动任何 servo（复用 walk_gait 思路）
  → 每帧发送前**在线预检**：|rotor_cmd − rotor_fb| > 0.5 rad ⇒ 立即 stop 退出
  → 按串口分组写 stdin @ ~100 Hz；读 FB 记录 命令/反馈/误差/温度
结束：全部 stop 松力
```

### 6.3 硬性安全约束（写进脚本，不可绕过）

1. **软增益默认** 转子 `kp≤4, kw≤0.1`；上调需显式参数 + 醒目告警。
2. **限速插值**，任何目标不许跳变。
3. **两级预检**：整段（开跑前）+ 每帧（在线），命中即松力退出。
4. **默认 `--air`**；承重轨迹需显式开关，本阶段占位报错。
5. **退出即松力**：正常/异常/Ctrl-C 都保证给所有进程 `stop`。
6. **先 `--dry-run`**：管线（映射/顺序/限速/预检）在 `SimMotorBus` 上全绿，才连真机。

## 8. 失败模式与排查

| 现象 | 可能原因 | 排查 |
|---|---|---|
| nudge 方向反 | `sim_sign` 该翻 | §5.2 回写 YAML，记事 |
| 站姿左右不对称 | 一侧 `sim_sign` 反 / hip 前后镜像坑 | 查 hip 轴 fl/fr=−X、rl/rr=+X（memory） |
| 站姿整体偏但对称 | `stand_rotor` 锚点漂了 | §5.4，重跑站姿标定 / `_reanchor` |
| crank 那路姿态怪 | shank 槽错当小腿、或第三电机通道串 | 核 §3 顺序表 |
| FB 跟不上命令 | 增益太软/限速太快/机构卡 | 降速、适当提 kp、查机械 |
| read 某 id 无响应 | 串口/供电/`.so` rpath（改名坑） | 手跑 `motor_ctrl <port> <id> read`、看 ldd |
| 小腿零增益缓慢下垂 | 重力反驱（memory 2026-07-05） | 标定/摆位让其靠限位再读 |

## 9. 里程碑与下一步

- **① 本文（映射验证 + 吊空验证）** ← 现在
- ② 增益换算与半承重：转子增益从软往走路值（关节侧 500 ⇒ 转子 ≈12.5、kw≈0.125）逐步靠；
  吊装半承重站立保持。
- ③ 低姿慢速触地：带吊装/人扶，`--vx 0.15`、长周期，验证真机能否开环迈步。
- ④ 若开环站不住（大概率）：上闭环姿态反馈 / 或转 RL 策略部署（`deploy/real/rl_deploy.py`
  已用同一 `motor_bus` 映射，可直接对比）。

> 任何时候都可停在「吊空验证通过」这个安全点，不必强推下地。
