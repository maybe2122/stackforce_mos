## 1. 当前 45 维观测构成

按 `_get_observations` 拼接顺序：

| 序号 | 维度 | 内容 | 坐标系/单位 | 真机来源 | 状态 |
|------|------|------|-------------|----------|------|
| 0–2 | 3 | `root_lin_vel_b` 机身线速度 | 机身系 m/s | **无传感器可测** | ⚠ 特权观测，部署喂 0 |
| 3–5 | 3 | `root_ang_vel_b` 机身角速度 | 机身系 rad/s | IMU 陀螺仪 | ⚠ 部署侧 IMU 仍为 stub（喂 0） |
| 6–8 | 3 | `projected_gravity_b` 重力方向投影 | 机身系单位向量，水平≈[0,0,−1] | IMU 姿态解算 | ⚠ 部署侧 stub（固定 [0,0,−1]） |
| 9–20 | 12 | `joint_pos − default_joint_pos` | rad | 电机编码器（转子÷6.33，经 stand_rotor 换算） | ✅ 已接通 |
| 21–32 | 12 | `joint_vel` | rad/s | 电机 FB 速度（转子÷6.33） | ✅ 已接通 |
| 33–44 | 12 | `last_actions` 上一帧动作 | clip(±1.5) 后原始值（未乘 action_scale） | 部署进程自持 | ✅ 已接通 |

**12 维块的关节顺序**：4 hip → 4 thigh → 4 shank，组内 fl, fr, rl, rr。

其他事实：

- **无任何归一化/缩放**：各分量物理原值直接拼接；仅有可选统一高斯噪声
  （`train.py --obs_noise_std`，默认 0）、NaN→0 清理、最终 clip ±100。
- **不含速度指令**：commands 是常量（前进 1 m/s）只进 reward，策略无法变速/转向，
  也没有"cmd=0=站立"的行为。
- **default_joint_pos 髋角约定**：当前 [0.15,0.15,−0.15,−0.15] 实际是整体右移
  （hip 轴前后镜像，见 2026-07-05 实测），非左右对称外撇。
- cfg 已预留**非对称 critic** 接口（critic 观测维度字段 + `"critic"` 输出键），未启用。

### 部署对齐现状（sim2real 缺口）

| 缺口 | 后果（2026-07-04 MuJoCo 实测） |
|------|-------------------------------|
| lin_vel 喂 0 | 策略以为没动 → 持续加速，行走崩溃 |
| IMU stub（ang_vel=0、gravity 固定） | 无姿态感知，不能真正平衡 |
| 训练增益 25/0.5 vs 部署 320/3.2 | 动力学完全不同，接管 0.12 s 摔倒（硬阻塞，另见部署文档） |

## 2. 优化方向分析

按优先级排序。P0 = 不改就无法部署；P1 = 显著影响 sim2real 质量；P2 = 锦上添花。

### P0-1 去掉特权 lin_vel（三条路线）

| 路线 | 做法 | 改动量 | 上限 | 建议 |
|------|------|--------|------|------|
| A. 直接删除 | obs 42 维，策略从 ang_vel/joint 史隐式推断 | 最小 | 中——盲走，速度跟踪精度差 | 可作 baseline |
| **B. 非对称 critic** | actor 42 维；critic 额外拿 lin_vel（cfg 已留接口） | 小 | 中高——训练信号不丢，执行不依赖 | **首选，先闭环** |
| C. HIM 估计器 | `him/train.py` 已集成：用观测历史在线估计速度并喂给 actor | 中 | 高 | B 跑通后升级 |

### P0-2 加入速度指令（42→45 或 45→48）

- obs 追加 3 维 `(vx_cmd, vy_cmd, ωz_cmd)`；`_reset_idx` 随机采样指令
  （含一定比例的 cmd=0，让"站立"成为策略内的一个行为，而不是另一个控制器）；
  reward 的 track 项改用动态指令。
- 这是可控行走、原地站立、以及后续遥控的前提。cfg 注释已写明改法（→48 那段）。

### P0-3 IMU 通道的真实化（与部署联动）

- 训练侧：ang_vel / projected_gravity 加**分通道**噪声 + 常值偏置随机化
  （模拟陀螺零偏、姿态解算误差），而不是现在的全 obs 统一 std；
- 部署侧：`rl_deploy.py` `_build_obs` 补真实 IMU 分支（serial/udp），
  MuJoCo 侧 `play_mujoco.py --imu-source` 用仿真 IMU 而非特权量做验证。

### P1-1 分通道观测缩放

当前各分量量纲悬殊（gravity ±1 vs joint_vel 可达 ±20 rad/s），网络输入分布不均衡，
且统一噪声 std 对不同通道的信噪比含义完全不同。建议引入常用缩放
（参考值：ang_vel ×0.25、joint_pos ×1.0、joint_vel ×0.05、gravity ×1.0），
或启用 rsl_rl 的 empirical normalization。**注意：缩放系数进部署契约，
`rl_deploy.py` / `play_mujoco.py` 必须同步**。

### P1-2 关节速度的真实化

真机 joint_vel 来自电机 FB 转子速度 ÷6.33，噪声和量化远差于仿真真值。
训练侧对 joint_vel 通道加较大噪声/随机延迟；或部署与训练统一改用位置差分+低通
（两侧必须同一种来源，否则又是一个隐性 gap）。

### P1-3 延迟与执行器建模

- 观测→动作→执行的真机链路有 1~2 个控制周期（20~40 ms @50Hz）延迟，
  训练侧加随机 action delay（0~2 步）能显著提升鲁棒性；
- 执行器：真机 PD 在转子侧闭环+减速器摩擦/背隙，仿真是理想关节 PD。
  先用增益/力矩上限随机化覆盖（±20% 已有雏形，env_cfg:150），
  背隙可结合本机滑齿事件教训：对 joint_pos 加小幅回差噪声。

### P1-4 默认髋角改对称

趁重训把 default_dof_pos 髋角改为 [−0.15,0.15,0.15,−0.15]（左右对称外撇，
`stand_balance.py` 已用此约定），消除"整体右移 17mm"的历史坑。
**改了它 = 改了 obs 第 9–20 维的零点 = 新契约**，部署侧 default_dof_pos 同步。

### P2-1 观测历史堆叠

单帧观测对噪声/延迟敏感。可堆叠近 N 帧（如 5 帧 → 每帧 45/48 维）或走 HIM
（路线 C 自带时序编码）。注意部署侧 50 Hz 环形缓冲同步实现。

### P2-2 步态相位/时钟信号

加 2~4 维正弦时钟可稳定步态频率、便于步态整形 reward，代价是策略依赖外部时钟、
灵活性下降。四足 trot 通常无时钟也能收敛，**暂不建议**，列此备查。

## 3. 建议的新契约（一次定死，训练=MuJoCo=真机）

```
obs (48) = ang_vel_b(3)·0.25 + projected_gravity_b(3) + cmd(3)
         + (joint_pos−default)(12) + joint_vel(12)·0.05 + last_actions(12)
（去 lin_vel；critic 侧额外 + lin_vel_b(3) 走非对称接口）
增益：关节侧 kp=320 / kd=3.2（=真机转子 8.0/0.08）
默认髋角：[−0.15, 0.15, 0.15, −0.15]（对称外撇）
噪声：分通道（IMU/编码器分开）+ 陀螺常值偏置随机化 + 0~2 步动作延迟
```

改契约涉及的文件（必须同步改，缺一个就是新的 sim2real gap）：

1. `mos2026_2_closed_usd_env.py` `_get_observations` / `_reset_idx`（指令采样）
2. `mos2026_2_closed_usd_env_cfg.py`（observation_space、default 髋角、增益、随机化）
3. `deploy/real/rl_deploy.py` `_build_obs`（顺序、缩放、cmd 来源）
4. `deploy/real/config/mos2026_2.yaml`（default_dof_pos、增益语义）
5. `deploy/mujoco/play_mujoco.py`（sim2sim 验证侧）
6. `deploy/real/policy_export.py`（输入维度）
