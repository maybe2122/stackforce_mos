# 姿态 PD 站立平衡控制器(传统控制 baseline · M1)

> 2026-07-05。对应 `todo.md`「运控技术栈缺口 3:传统控制 baseline」的第一步。
> 代码:[`deploy/mujoco/stand_balance.py`](../deploy/mujoco/stand_balance.py)(~260 行,含实验)。
> 控制逻辑本体只有 ~30 行,是**白盒**——每一行都能解释,出问题能定位到层。

---

## 一、定位:为什么先做这个

- **RL 的对照组与回退模式**:出问题时用它二分「硬件问题 vs 策略问题」;RL 失败时有东西可退。
- **RL 部署的脚手架**:它要打通的链路——IMU 读数 → 坐标系约定 → 50 Hz 控制环 →
  伺服下发 → 安全急停——和 RL 部署**完全相同**,但控制逻辑只有 30 行。
  用白盒把整条硬件链路调通,再换黑盒策略,是运控工程的标准打法。
- 现状对比:真机站立(robot_web)是**开环插值**,把关节锁在标定位,推一下只能靠
  关节刚度硬扛且留静差;本控制器是**闭环**,主动回平。

## 二、控制律(50 Hz)

```text
g_b  = R^T·[0,0,-1]                       ← 机身系投影重力(仿真=真值;真机=IMU 姿态融合输出)
g_f  += α·(g_b − g_f)                      ← 一阶低通,α=0.25(50 Hz 下截止 ≈2.3 Hz)
u    = kp_att·g_f[0:2] + kd_att·ġ_f[0:2]   ← 姿态 PD,微分作用在【滤波后】的信号上
Δz_i = −(u_x·sx_i + u_y·sy_i)              ← 每腿足端高度修正:低的那侧腿伸长
Δq_i = J_i⁺·Δz_i                           ← 数值雅可比伪逆 → (thigh, 曲柄) 修正
Δq   = slew_limit(clip(Δq))                ← 分区限斜率(见 §四)
target = default_pose + Δq                 ← 叠加站姿目标,下发位置伺服
```

符号约定:`g_f[0]>0` = 机头低 → 前腿(sx=+1)伸;`g_f[1]>0` = 左侧低 → 左腿(sy=+1)伸。
伸腿 = 足端 z(机身系)更低,故取负号。每腿足端 (x,y) 符号在启动时从模型自动读取。

**雅可比不拍脑袋**:`J_i = ∂(足端z)/∂(thigh, 曲柄)` 在站姿处数值求取——给定受驱角,
闭链被动角用 connect 锚点重合的最小二乘解算(`ClosedChainKin`,以站姿解为初值局部
求解,保证停在正确装配分支),再中心差分。实测本机型:`J ≈ [±0.143, 0.000] m/rad`。

## 三、高频震动问题:根因与修复(2026-07-05 实录)

初版控制器在 viewer 里表现为**站立时高频抖动**。量化(稳态 2 s 静立的指令步变化):
初版 **19.9 mrad/步**(>10 即目测明显)。两个根因:

1. **反馈增益过高**:`kp_att=0.6` 经雅可比伪逆(≈7 rad/m)放大,零点几度的倾角
   就产生零点几 rad 的关节修正,kp=320 硬伺服瞬间执行 → 过冲 → 反向修 → 极限环;
2. **微分项吃了未滤波信号**:`ġ` 用相邻帧差分,落脚冲击让投影重力每帧跳变,
   微分项把冲击噪声直接放大成关节指令抖动。

**抗抖三件套**(修复后稳态抖动 = 0.0 mrad/步):

| 措施 | 参数 | 作用 |
|---|---|---|
| 姿态一阶低通 | α=0.25(截止 ≈2.3 Hz @50 Hz) | 落地冲击的高频分量进不了控制回路 |
| 降比例增益 | kp_att 0.6→**0.3** | 0.3 是实验扫出的**起振边界**(见下) |
| 分区限斜率 | 静立 0.02 rad/步;倾角>3° 时 ×4 | 静立温柔零抖动;大扰动时快速回中 |

**增益上限是结构性的,不是调参手感**:实验扫描 kp_att ∈ {0.3, 0.45, 0.5, 0.6},
0.3 静立零抖动,0.45 起 18.5 mrad/步,再高全部起振——低通滤波引入相位滞后,
闭环稳定裕度就卡在 0.3 附近。**抗扰要靠分区斜率放开响应速度,不能靠拉增益**。

## 四、实验结果(MuJoCo,部署增益 kp=320/kv=3.2,侧向速度冲量扫描)

| 侧向冲量 | 无控制器 | 有控制器(平滑版) |
|:--:|:--|:--|
| 0.2~0.8 m/s | 峰值 4~6°,**残余 3.5°(歪着不动)** | 峰值 1~5°,**残余 ≈1.0°(回平)** |
| 1.0 m/s | 峰值 12.0°,残余 3.5° | 峰值 10.2° → **残余 1.0° 完全回平** |
| 1.2 m/s | 倾覆 | 倾覆 |

诚实结论:
- **价值在主动回平**,不在倾覆阈值——无控制器时伺服静差让机器人被推后一直歪着
  (3.5°),有控制器 2 s 内回到 ≈1°;
- **倾覆阈值不变(1.2 m/s)**:超过它机身瞬间到 90°+,「伸腿调平」类策略物理上
  救不了,需要**迈步恢复(capture point)**——那是下一层级的控制器,不属于站立平衡;
- 曾有一版"阈值 1.2→1.5"的结果,是初版高增益抖动换来的,真机上那种指令会烧电机,
  **不作数**。

## 五、工程发现(真机同样适用)

1. **曲柄雅可比奇异**:站姿(全零)处曲柄对足端高度的偏导 ≈0——四连杆接近伸展
   奇异,高度修正全部走 thigh。真机站姿同构,做站立控制时不要指望 shank 电机调高度。
2. **kp_att>0.3 必起振**:见 §三。真机 IMU 比仿真真值更吵,这个上限只会更低。
3. **微分项永远作用在滤波后的信号上**,且输出要限斜率——这两条对将来 RL 部署的
   动作后处理(`--action-lpf`)是同一个道理。

## 六、怎么跑

```bash
# headless 推搡对比实验(默认:平衡开;--no-balance 跑对照组)
../env_isaaclab/bin/python deploy/mujoco/stand_balance.py
../env_isaaclab/bin/python deploy/mujoco/stand_balance.py --no-balance

# viewer 直观看(每 3 s 自动侧推 0.4 m/s)
MUJOCO_GL=glx ../env_isaaclab/bin/python deploy/mujoco/stand_balance.py --viewer

# 调参入口
--kp_att 0.3 --kd_att 0.05    # 姿态 PD(注意 kp_att>0.3 起振)
--kp 320 --kv 3.2             # 伺服增益(部署等效;kp=25 软伺服撑不住自重,见 play_mujoco)
--pushes 0.5 1.0 1.5          # 自定义推搡扫描序列
```

输出判读:`稳态抖动 max|Δq_cmd|` >10 mrad/步即目测明显抖;推搡表看「2s后倾角」
是否回到 ≈1°。

## 七、下一步(M2/M3)

- **M2 真机版(IMU 到货后,半天)**:`StandBalance` 的输入就是一个机身系投影重力
  向量 + dt,把仿真真值换成 IMU 姿态融合输出即可,控制律一行不用改。搬进
